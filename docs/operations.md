# 운영 인수와 확장 기준

실제 학교 책임자·예산·운영 계약은 미지정이다. 아래는 서비스 운영 전에 인수할 역할과 검사 항목이며 현재 담당자가 배정됐다는 뜻이 아니다.

| 역할 | 맡을 자료/작업 | 시스템 경로 |
| --- | --- | --- |
| 자료 편집 담당 | 공간 ID·명칭·출처·기준일·확인 상태·공개 범위 | editor 초안/제보 처리 |
| 검토 담당 | 실측/통행/운영 근거, 만료일, 변경 영향 | reviewer 검토/승인/공개·운영 등록 |
| 플랫폼 관리자 | 계정/권한·백업·이전판·보안·장애 | admin·CLI·API 상태/감사 |
| 시설/접근성 담당 | 문·계단·승강기·폭/경사·공사/폐쇄 | 현장 조사 후 검증 그래프/운영 기록 |
| 학교 연동 담당 | endpoint·권한·자료 계약·갱신 간격·사용권 | 비공개 공급자 설정/동기화 |

부지/모델 확장은 동일 캠퍼스 자료의 정밀화를 먼저 완료하고, 독립 원점·부지·자료·사용권·관리 권한이 확보된 다음 캠퍼스를 등록한다. 기본 제공은 한신대학교 경기캠퍼스만이다. 다른 학교를 데모 이름/가짜 모델로 채우지 않는다. 정밀 자산은 기존 영구 공간 ID를 유지한 채 GLB provider로 교체하며 단위/축/원점/출처를 검토한다. 원시 IFC는 구현된 선택 변환 CLI와 별도 Python 도구를 사용하며 공개 요소 허용 목록·사용권·형상 검수를 거친다. 학교 IFC 원본은 미확보다. 제작 계약은 [3D 자산 제작](refinement-assets.md)을 따른다.

## 인수 검사

자료마다 출처·기준/관측/검토일·좌표/단위·확인 상태·만료일·공개 범위를 확인한다. 도형·참조·버전 검증 통과 뒤 변경 비교→제출→다른 검토자 승인→새 불변 공개판으로 게시한다. 실제 경로는 현장 통행과 접근성 조사 없이 인수하지 않는다. 추정 안내 경계를 법적 소유 경계로 인수하지 않는다.

배포는 staging에서 로그인·scope·초안/공개·복구·제보·오프라인·자산/health를 확인하고 온라인 백업을 만든 뒤 운영한다. 실제 배포/컨테이너/CI·HTTPS·복구 훈련은 아직 확인하지 않았다. 담당 부서와 보존/삭제기간·제보 처리 목표·보안 연락·휴일 대응을 합의해야 한다.

## 비용과 성과

비용 산정은 실측/GIS/실내 평면 조사, GLB 변환·최적화, 서버/스토리지/백업/트래픽, 자료 갱신 인력, 접근성·실기기·보안 검사, 장애 대응을 구분한다. 실제 견적·사용량·학교 예산이 없어 금액을 산정하지 않았다. 공급자별 사용권과 유료 호출 조건을 확인한 뒤 계약한다.

구현된 서버 지표는 요청·오류·충돌·제보·게시 수와 시작 시각이다. 구조화 로그의 requestId/operation/duration/status로 오류를 추적한다. 프로세스 지표는 재시작 시 초기화되며 감사·제보·공개판은 DB에 남는다. 상세 로더·장면 진단은 상태/오류·FPS·mesh 수·품질을 제공한다.

현장 사용 성과는 아직 측정하지 않았다. 운영 목표를 정할 때 첫 화면 표시 시간, 주요 기기 FPS/메모리/발열, 검색 성공률, 실제 목적지 도착률, 접근성 이용 성공률, 자료 만료율, 제보 처리 시간, 오류율/복구 시간, 저장 용량/트래픽을 측정한다. 자동 Chromium/NullEngine 결과를 실제 사용자의 성과나 현장 안전 검증으로 바꾸지 않는다. 개인 검색어·정확한 위치·시간표를 서버 성과 로그에 수집하지 않는다.

AI 도우미는 승인 자료의 검색/출처 안내와 등록 HTTPS 공급자 어댑터를 제공한다. 공급자가 반환한 공간/출처 ID를 현재 승인 자료와 검증하고 표시 내용은 승인 자료에서 다시 구성한다. 실제 공급자는 미설정이다. VR은 WebXR 세션·이동/회전 설정을 제공하며 AR은 hit-test·기준점/독립 검수점 정합·오차 및 추적 손실 차단을 구현했다. 검수된 AR 현장 앵커는 미등록이고 실제 AR/VR 기기 이용·안전/멀미는 미검증이다. 공간 정합·개인정보·기기 안전·출처 응답·책임 범위는 [인수 프로토콜](refinement-acceptance.md)에 따라 검수한다.

기능별 상태는 [32개 확장 항목](expansion-status.md)과 후속 [42개 고도화 항목](refinement-status.md), 명령/설정은 [배포](deployment.md), 검사 증거는 [검증](validation.md)을 따른다. 공개판에 봉인된 파일은 재빌드로 바뀌지 않는다. 새 런타임을 승인판 오프라인 묶음에 제공할 때는 새 자료/자산 버전의 초안을 검토·승인·공개한다.
