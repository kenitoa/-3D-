# 한신대학교 경기캠퍼스 3D 모델링 웹사이트

이 프로젝트는 한신대학교 경기캠퍼스를 Babylon.js 기반 3D 장면으로 재구성한 웹사이트입니다. 사용자는 브라우저에서 캠퍼스 지형, 건물 외관, 도로와 보행 동선, 건물별 내부 평면 정보를 함께 볼 수 있습니다. 단순히 건물 모형만 놓는 것이 아니라, 공개 자료로 확인한 건물명, 건물 번호, 주요 시설, 층별 내부 기능, 캠퍼스 지형 단서를 하나의 탐색 화면으로 묶는 것을 목표로 합니다.

현재 웹사이트는 `index.html`을 중심으로 동작하는 정적 웹 페이지입니다. 별도 서버나 백엔드 없이 Babylon.js CDN과 로컬 JavaScript 파일을 불러와 3D 장면을 구성합니다. 사용자는 화면을 이동하며 캠퍼스를 둘러보고, 각 건물을 클릭해 내부도와 조사 근거를 확인할 수 있습니다.

## 프로젝트 목적

이 웹사이트의 핵심 목적은 한신대학교 경기캠퍼스의 공간 구조를 시각적으로 이해하기 쉽게 만드는 것입니다.

기존의 캠퍼스 안내 자료는 보통 평면 지도, 건물 목록, 공지의 장소명, 사진 자료가 서로 흩어져 있습니다. 이 프로젝트는 그 자료들을 모아 다음과 같은 방식으로 재구성합니다.

- 캠퍼스의 큰 지형 흐름을 3D 지면으로 표현합니다.
- 공개 자료에서 확인되는 건물 위치와 용도를 건물별 3D 모델로 표현합니다.
- 각 건물을 클릭하면 내부 기능과 층별 공간 구성을 볼 수 있게 합니다.
- 실제 도면이 공개되지 않은 영역은 확정값처럼 단정하지 않고, 공개 근거 기반 추정 평면으로 분리해 표시합니다.
- 조사 근거는 `search.md`에 남겨, 이후 모델링 수정 시 어떤 자료를 바탕으로 반영했는지 추적할 수 있게 합니다.

## 실행 방법

가장 간단한 실행 방법은 프로젝트 폴더의 `index.html`을 브라우저에서 여는 것입니다.

```text
index.html
```

브라우저에서 열면 다음 파일들이 순서대로 로드됩니다.

- `src/data/campus-data.js`
- `src/data/interior-data.js`
- `src/models/*.js`
- `src/ui/hud.js`
- `src/app.js`

Babylon.js는 CDN에서 불러옵니다.

```html
<script src="https://cdn.babylonjs.com/babylon.js"></script>
<script src="https://cdn.babylonjs.com/gui/babylon.gui.min.js"></script>
```

인터넷 연결이 없는 환경에서는 Babylon.js CDN을 불러오지 못하므로 화면이 정상적으로 실행되지 않을 수 있습니다. 오프라인 실행까지 필요하다면 Babylon.js 파일을 로컬에 내려받아 `index.html`의 CDN 경로를 로컬 경로로 바꾸는 작업이 필요합니다.

## 화면 구성

웹사이트는 크게 세 영역으로 구성됩니다.

첫 번째는 전체 3D 캠퍼스 장면입니다. 사용자가 가장 먼저 보는 화면으로, 지형 메쉬, 건물 외관, 도로, 보행로, 주차장, 스케일 표시가 배치됩니다.

두 번째는 상단 정보 바입니다. 화면 왼쪽 위에 표시되며 프로젝트 이름, 모델링 범위, 내부도 반영 상태를 요약합니다.

세 번째는 건물 내부 상세 패널입니다. 건물을 클릭하면 화면 전체에 가까운 큰 패널이 열리고, 건물의 내부 평면도, 층 선택 탭, 확인된 내부 요소, 공간 구성, 자료 기준, 배치 기준을 보여줍니다.

## 첫 화면 흐름

사용자가 사이트에 들어오면 `index.html`이 전체 화면 캔버스를 표시합니다.

```html
<canvas id="renderCanvas" aria-label="한신대학교 Babylon.js 3D 캠퍼스 모델"></canvas>
```

그 위에 상단 바가 고정 표시됩니다. 상단 바는 현재 프로젝트가 한신대학교 경기캠퍼스 3D 모델링이며, 외관 모델과 건물별 내부 평면 상세화를 포함한다는 점을 알려줍니다.

초기 카메라는 장공관과 캠퍼스 중심부를 보기 좋은 위치에 놓입니다. 사용자는 키보드와 마우스로 장면을 탐색할 수 있습니다.

## 조작 방식

현재 조작 방식은 Babylon.js의 `UniversalCamera`를 사용합니다.

- 마우스 드래그: 시점 회전
- 키보드 W: 앞으로 이동
- 키보드 S: 뒤로 이동
- 키보드 A: 왼쪽 이동
- 키보드 D: 오른쪽 이동
- 건물 위에 마우스 올림: 건물명 라벨 표시
- 건물 클릭: 해당 건물 내부 상세 패널 열기
- 상세 패널의 닫기 버튼 또는 Esc: 내부 상세 패널 닫기
- 상세 패널의 층 탭 클릭: 해당 층 평면으로 전환

## 캠퍼스 장면 설명

캠퍼스 장면은 실제 캠퍼스 안내 자료와 공개 지도 데이터를 바탕으로 만든 모델링용 좌표계 위에 구성됩니다. 프로젝트 내부 좌표는 실제 지리 좌표 그대로가 아니라, Babylon.js 장면에서 보기 쉽도록 변환된 좌표입니다.

현재 전체 기준은 다음과 같습니다.

- 설계 축척: `1:1000`
- Babylon 단위 기준: `1 unit = 10m`
- 스케일 바 기준: `100m`
- 모델링 기준 범위: 동서 장축이 긴 캠퍼스 영역

지형은 단순 평면이 아니라 표고 차를 가진 메쉬로 구성됩니다. `campus-data.js`의 7x7 표고 샘플을 바탕으로 지형 높이를 보간하고, 독산성·세마대 방향의 산지 흐름과 황구지천 방향 저지대 흐름을 보정값으로 더했습니다.

다만 현재 지형은 정밀 측량 DEM 원본이 아니라 공개 표고 샘플과 공개 지형 설명을 바탕으로 만든 모델링용 지형입니다. 실제 지형과 완전히 동일한 수치 모델이라고 보기는 어렵고, 공개 자료 범위에서 캠퍼스의 고저 차를 더 잘 보이게 만든 구현입니다.

## 건물별 내부 상세 화면

건물을 클릭하면 내부 상세 패널이 열립니다. 이 패널은 `src/ui/hud.js`에서 생성합니다.

내부 상세 화면은 다음 요소로 구성됩니다.

- 건물명
- 건물 기능 요약
- 확인된 층 범위
- 층별 탭
- 내부 평면도
- 공간 종류별 색상 범례
- 확인된 내부 요소 목록
- 핵심 공간 구성
- 자료 기준
- 배치 기준

내부도는 실제 건축 도면을 그대로 복원한 것이 아닙니다. 공개 자료에서 확인된 층수, 호실, 기관명, 시설명, 건물 기능을 바탕으로 축소한 개념 평면입니다. 그래서 상세 패널에는 계속 `공개자료 기반 축소 평면`, `확인된 내부 요소`, `자료 기준`, `배치 기준`이라는 표현을 사용합니다.

## 내부도 데이터 기준

내부도 데이터는 `src/data/interior-data.js`에 들어 있습니다. 각 건물은 `CampusData.<building>Interior` 형태의 객체로 정의됩니다.

각 내부도 객체는 보통 다음 구조를 가집니다.

- `id`: 내부도 식별자
- `title`: 상세 패널 제목
- `subtitle`: 건물 기능 설명
- `floor`: 확인된 층 범위
- `source`: 공개자료 기준 설명
- `note`: 배치 기준 또는 추정 범위 설명
- `confirmed`: 공개 자료에서 확인된 내부 요소 목록
- `zones`: 평면도에 배치되는 구역 목록
- `rooms`: 핵심 공간 설명 목록
- `footprints`: 건물 외형을 반영한 평면 배경 윤곽

`zones`는 퍼센트 좌표를 사용합니다. 예를 들어 `x`, `y`, `w`, `h`는 상세 패널 내부 평면 영역의 상대 위치와 크기를 의미합니다.

```js
{ id: "pilheon-office", label: "대학원\n교학팀", kind: "office", x: 12, y: 45, w: 30, h: 22 }
```

이 방식은 실제 픽셀 좌표가 아니라 패널 크기에 맞춰 자동으로 늘어나는 구조입니다. 화면 크기가 달라져도 내부 구역의 상대 배치가 유지됩니다.

## 층 구분 방식

내부도는 한 화면에 모든 층을 겹쳐 보여주지 않고, 층 탭으로 분리합니다. 사용자가 특정 층을 선택하면 해당 층의 공간만 표시됩니다.

층 구분은 두 방식으로 처리됩니다.

첫 번째는 데이터에 `floor` 또는 `level` 값이 명시되어 있는 경우입니다. 이 경우 해당 값을 그대로 사용합니다.

두 번째는 명시 값이 없는 경우입니다. `hud.js`의 `inferZoneFloor()` 함수가 구역 id, 라벨, 건물의 층 설명을 읽고 `B1`, `1F`, `2F`, `3F`, `4F`, `5F`, `생활관`, `외부`, `공통` 같은 그룹으로 분류합니다.

이 구조 덕분에 건물별 내부 구역이 많아져도 상세 패널에서 층별로 정리되어 보입니다.

## 자료 조사 흐름

프로젝트의 조사 기록은 `search.md`에 정리되어 있습니다. 이 파일은 단순 출처 모음이 아니라, 어떤 기준으로 모델링에 반영했는지를 남기는 작업 로그 역할을 합니다.

조사 기준은 다음과 같습니다.

- 한신대학교 공식 페이지와 공지를 우선 사용합니다.
- 새내기한신 가이드, 생활관 안내, 도서관 안내, 센터 안내처럼 학교가 직접 제공하는 자료를 우선합니다.
- 공식 자료가 부족한 경우 공개 캠퍼스 소개 자료, 부동산/건축 정보, 기사 자료를 보조 근거로 사용합니다.
- 실내 원도면이 없는 경우 실제 도면처럼 단정하지 않습니다.
- 공개자료에 없는 방 개수, 문 위치, 복도 폭, 설비실 위치는 확정값으로 적지 않습니다.

웹사이트 안에서는 `Search.MD`라는 파일명을 노출하지 않고, 사용자가 이해하기 쉬운 `캠퍼스 공개 조사 자료`라는 표현을 사용합니다.

## 화면 디자인 방향

이 웹사이트는 홍보용 랜딩 페이지가 아니라 캠퍼스 공간을 탐색하는 도구에 가깝습니다. 따라서 화면 디자인은 장식보다 정보 식별성을 우선합니다.

현재 디자인 방향은 다음과 같습니다.

- 배경은 3D 캠퍼스 자체가 주인공이 되도록 전체 화면 캔버스로 구성합니다.
- 상단 바는 작고 단단하게 고정해 프로젝트 상태만 알려줍니다.
- 내부 상세 패널은 건물별 조사 자료를 읽기 쉽게 큰 패널로 표시합니다.
- 내부 평면은 층 탭, 구역 번호, 공간 종류 라벨, 범례를 함께 사용해 읽기 쉽게 구성합니다.
- 너무 많은 선형 보조 요소는 지저분해 보일 수 있어 도로와 보행로를 단순화하고, 입구 방향 보조선과 초록색 사면 패치는 화면에서 제거했습니다.

## 주요 파일 안내

```text
index.html
```

웹사이트의 진입점입니다. CSS, 캔버스, 상단 바, 상세 패널 컨테이너, Babylon.js CDN, 로컬 스크립트 로딩 순서를 포함합니다.

```text
src/app.js
```

실제 브라우저가 실행하는 메인 스크립트입니다. 장면 생성, 카메라, 조명, 재질, 지형, 도로, 건물 생성, HUD 연결, 클릭 동작을 담당합니다.

```text
src/app.ts
```

`app.js`와 같은 내용을 가진 TypeScript 원본 성격의 파일입니다. 현재 프로젝트는 별도 빌드 없이 `app.js`를 직접 로드하지만, 코드 구조와 타입 확인을 위해 `.ts` 파일도 함께 유지합니다.

```text
src/data/campus-data.js
```

캠퍼스 전체 데이터입니다. 캠퍼스 기본 정보, 축척, 지형 표고, 건물 대지 패드, 옹벽, 캠퍼스 경계, 도로/보행로, 입구 방향, 조사 메모가 들어 있습니다.

```text
src/data/interior-data.js
```

건물별 내부 상세 데이터입니다. 각 건물의 층, 확인된 공간, 평면 구역, 핵심 실 목록, 자료 기준이 들어 있습니다.

```text
src/models/*.js
```

건물별 외관 모델 파일입니다. Babylon.js MeshBuilder를 사용해 각 건물의 본동, 부속동, 창, 출입부, 지붕, 장식 요소를 만듭니다.

```text
src/ui/hud.js
```

HUD와 내부 상세 패널을 담당합니다. 건물 라벨, 스케일 바, 클릭 이벤트, 내부도 HTML 생성, 층 탭 전환을 처리합니다.

```text
search.md
```

조사 기록 파일입니다. 모델링에 반영한 공개 자료, 판단 기준, 한계, 추가 조사 내용을 정리합니다.

```text
tsconfig.json
```

TypeScript 검사 설정입니다. 현재 `noEmit`이 켜져 있어 빌드 산출물을 만들기보다는 타입 확인 용도로 쓰는 구조입니다.

## 사용자 경험 흐름

사용자는 먼저 캠퍼스 전체를 둘러봅니다. 건물 위에 마우스를 올리면 이름이 표시되므로, 어떤 건물인지 빠르게 확인할 수 있습니다.

관심 있는 건물을 클릭하면 상세 패널이 열립니다. 패널의 왼쪽에는 내부 평면도가, 오른쪽에는 조사 근거와 핵심 공간 설명이 표시됩니다. 내부 평면도 위쪽에는 층 탭이 있어 건물의 층별 구성을 구분해서 볼 수 있습니다.

사용자가 다른 건물을 보고 싶으면 패널을 닫고 다시 3D 장면에서 다른 건물을 클릭하면 됩니다. 건물 클릭 시 카메라도 해당 건물 쪽으로 이동해, 사용자가 어떤 건물을 선택했는지 장면 안에서 바로 확인할 수 있습니다.

## 프로젝트의 현재 상태

현재 프로젝트는 완성형 배포 사이트라기보다, 공개자료 기반 캠퍼스 3D 모델링을 계속 보강하는 작업형 프로토타입입니다.

이미 구현된 핵심 기능은 다음과 같습니다.

- 전체 화면 3D 캠퍼스 장면
- 16개 건물 외관 모델
- 16개 건물 내부도
- 층별 내부도 탭
- 건물 hover 라벨
- 건물 click 상세 패널
- 지형 표고 메쉬
- 건물별 지형 높이 보정
- 도로/보행로 단순화 렌더링
- 공개 조사 자료 기록

앞으로 정확도를 더 높이려면 실제 캠퍼스 도면, 정밀 수치지형도, 더 많은 외관 사진, 실내 평면 자료가 필요합니다. 현재 코드는 그런 자료가 추가될 때 건물 데이터와 내부도 데이터를 계속 확장할 수 있도록 파일을 분리해 둔 상태입니다.
