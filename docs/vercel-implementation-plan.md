# Vercel 전체 기능 배포 계획

## 목적과 범위

Vercel 정적 화면과 Node.js API 함수에서 관리자·제보·승인·불변 공개판을 제공한다. 외부 libSQL(Turso) DB를 사용해 기존 SQLite 스키마와 데이터, scrypt 비밀번호, 역할·캠퍼스 범위·CSRF 규칙을 유지한다. 기존 로컬 SQLite 실행도 유지한다.

## 영향과 데이터 흐름

- `server`: 비동기 DB 어댑터, 트랜잭션, 공유 속도 제한, 불변 자산 저장.
- `api`와 `vercel.json`: 기존 `/api/v1`·공개 자산 경로 연결, 보안 헤더, 정적 `dist` 제공.
- `scripts`: 서버 빌드, 비파괴 백업·이전, 외부 DB 관리.
- `tests`, 환경 예제, 배포·DB·보안 문서: 기존 계약과 원격 실행 검증.

브라우저 → 동일 출처 Vercel 함수 → HTTPS libSQL DB. 비밀 DB 토큰은 서버 환경에만 전달한다. 사진과 관리자 자료는 공개 정적 산출물에 포함하지 않는다. 승인된 자산은 SHA를 유지해 외부 DB에 보관하고 공개된 자산만 읽을 수 있게 한다.

## 구현 순서

1. 비동기 SQL·트랜잭션 어댑터와 추가 마이그레이션을 작성한다. 적용된 마이그레이션 1~3은 수정하지 않는다.
2. 기존 API를 비동기 DB로 연결하고 동시 수정·중복 제보·공유 제한을 검증한다.
3. Vercel 함수, 자산 응답, 헤더와 파일 포함 설정을 추가한다.
4. 기존 SQLite 온라인 백업과 빈 외부 DB로의 재개 가능한 이전 도구를 제공한다. 원본 DB를 삭제하거나 덮어쓰지 않는다.
5. 린트·타입·기존 테스트·추가 원격 어댑터/동시성·브라우저·빌드를 실행한다.
6. 사용자의 Turso 계정과 DB 연결을 준비하고 데이터 이전 후 건수·무결성을 확인한다.
7. Vercel 환경 변수와 Git 연결을 설정하고 실제 health·로그인·제보·승인·자산을 확인한다.

## 위험과 대응

- 원격 지연·트랜잭션 만료: 요청 타임아웃, 원자적 변경, 실패 시 롤백. 성공 여부가 불명확한 쓰기는 자동 재시도하지 않는다.
- 다중 함수의 중복 실행: DB 제약조건과 트랜잭션으로 revision·멱등성을 재검증한다. 속도 제한은 DB에서 공유한다.
- Vercel 응답 크기 제한: 큰 불변 자산은 스트리밍으로 제공한다. 사진·JSON 입력은 기존 크기 제한을 유지한다.
- 이전 중 데이터 변경: 온라인 백업을 먼저 만들고 그 불변 백업에서 이전한다. 최종 전환 때 기존 서버의 쓰기를 멈추고 차이를 확인한다.
- 계정·비밀·사진 유출: 비밀을 출력·커밋하지 않고 DB 연결은 서버에서만 사용한다. 사용자 비공개 데이터를 옮기는 실제 외부 작업은 대상 DB를 확정한 뒤 진행한다.

## 검증과 롤백

로컬 SQLite와 libSQL 어댑터에서 동일 API 계약, 이중 승인·게시 경쟁, 제보 멱등성, 공유 제한, 이전 실패·재개, BLOB 해시를 검증한다. 외부 DB 권한이 없으면 실제 원격 검사와 공개 배포를 미완료로 보고한다.

기존 SQLite·백업을 보존한다. 새 배포 실패 시 이전 Vercel 배포로 전환하거나 기존 로컬 서버를 복구한다. 새 DB에서 발생한 쓰기를 버리지 말고 따로 보존한 뒤 동기화한다. 새 마이그레이션은 추가 테이블만 만들어 기존 로컬 앱의 핵심 데이터 호환성을 유지한다.
