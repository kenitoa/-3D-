# 확장 버전 3D 고도화 구현 계획

기준일: 2026-10-07. 사용자 승인 범위는 대화에서 작성한 42개 고도화 항목 전체다. 기존 초록·베이지 화면, 전체 부지 중심 구성, 16개 모델, 기존 저장·공간 ID·권한·공개판 계약과 사용자 변경을 보존한다. 실제 학교 자료가 없는 형상·통행·운영 정보를 임의로 만들지 않는다.

## 목적과 데이터 흐름

전체 부지를 먼저 읽고 캠퍼스→건물→층→공간을 탐색한다. 출처/좌표/자산 규격 검사→공간 편집과 같은 시점 비교→다른 검토자의 승인→자료/자산이 일치한 공개판→3D/2D/문자/오프라인의 동일 ID 흐름을 강화한다. 런타임은 기본 형상을 유지하면서 선택/가시영역/배경 순서로 상세와 LOD를 처리한다. 외부 연동·IFC·AR·XR는 명시적 입력/설정/기기 지원을 검사하고 실패를 숨기지 않는다.

## 영향과 역할

- 장면: `src/scene/site-scene.js` — 경계 의미/접지 진단/충돌/가림/카메라/선택 상태.
- 자산/순수 규칙: `src/scene/model-loader.ts`, `src/domain/refinement.js`, 제작 CLI — 여러 단계 모델/자원 예산/재현 가능한 자산 검수/정합/변환.
- UI: 플랫폼/관리자 컨트롤 — 목적/계층/측정/비교/검수/기기 설정. 기존 표시·저장·권한 계약 유지.
- 통합: `src/bootstrap.ts`, 타입, 공개 정적 목록, 오프라인, 서버 — 새로운 기능의 실제 호출과 공개판/자산/자료 일치 검증.
- 문서/검사: 항목별 상태표·제작 규격·검수 및 인수 표·자동/브라우저 증거. 실제 자료/실기기/운영 인수와 자동 검사를 구별.

## 구현 순서

1. 기존 파일·검사·계약을 확인하고 변경 중인 파일 소유를 나눠 병행한다.
2. 순수 규칙/장면/로더/UI를 기존 API에 하위 호환되게 추가한다.
3. 부트스트랩에서 실제 장면·카메라·로더·새 UI를 연결하고 정적/오프라인 자산 목록을 갱신한다.
4. 서버는 공개판의 자산 검증과 권한을 경계에서 확인하고 불변 파일/자료를 함께 관리한다. 스키마를 바꾸는 경우 새 마이그레이션만 추가한다.
5. 관련 테스트→전체 lint/typecheck/test/build/generated→데스크톱/모바일 브라우저·원래 기능 회귀 순서로 검사한다.
6. 최신 배포 산출물을 로컬 실행하고 42개 반영표에 구현·실행 증거·외부 인수 조건을 기록한다.

## 주요 위험과 대응

- 잘못된 정밀화: 추정 원본의 한계를 유지하며 자료 근거 없는 형상/경로/법적 경계를 생성하지 않는다.
- LOD와 자산 수명: 교체 후 ID/위치 유지, 이전 자산 해제·동시 로딩 취소·캠퍼스 전환 회귀를 검사한다.
- 개인정보/공개 자산: private/sensitive 공간의 도형/속성/사진이 공개 목록과 오프라인에 포함되지 않도록 검증한다.
- 외부 도구/모델: 입력 크기/경로/타임아웃/출력 형식을 제한한다. 변환 도구나 공급자 설정이 없으면 명시적으로 준비 조건을 표시한다.
- 자동 검사 오인: 합성 fixture/소프트웨어 WebGL 결과를 학교 자료·현장 GPS·실기기·법적 검수로 보고하지 않는다.
- 공개판 혼합: 자료와 자산 해시/버전을 같이 검사하고 미완료 묶음은 공개하지 않는다.

## 검증과 롤백

의미 있는 단위·통합 검사는 경계/정합/LOD/취소/자원 정리/측정/권한/공개 자산/오프라인 원자성을 확인한다. 브라우저는 전체 부지·목적/계층·선택/카메라·동작 줄이기·측정/층 보기·관리 검수·네트워크 단절과 기존 PNG/QR/제보를 확인한다. 실제 기기와 현장 인수는 별도 프로토콜과 기록 양식을 제공한다.

기존 사용자 변경을 되돌리지 않는다. 새 기능은 기본 형상과 기존 공개판으로 복귀할 수 있고, 공개판 복구는 기존 관리자/백업 경로를 사용한다. 새 DB 구조는 추가 마이그레이션으로만 적용하며 삭제/초기화를 하지 않는다. 외부 자료가 없는 인수 조건은 미완료로 보고한다.
