# 한신대학교 전체 조감도 정교화 실행 계획

사용자 승인 범위: 2026-10-07 대화에서 제안한 25개 기획 전체. 기존 Babylon.js 전체 화면, 녹색·베이지 시각 언어, 16개 건물 외관과 내부 상세를 유지한다.

## 목적과 데이터 흐름

학교가 어디까지인지, 각 건물·빈 공간·길·지형이 어떻게 연결되는지 첫 화면에서 파악한다. 공식 자료 및 지도 원자료 → 출처와 신뢰 수준 → 공통 미터 좌표 → 부지·지형·외부 시설·기존 모델 정합 → 전체/평면/자유 탐색 → 공간 정확성·사용성 검증의 순서로 구현한다.

## 구현 순서와 담당 컴포넌트

1. `site-plan`, `site-geometry`, `evidence`: 경계·건물·동선·시설 자료 수집, 좌표계 및 출처 관리. 캠퍼스 안내 영역, 도시계획시설, 소유 경계, 주변 문맥을 구분한다.
2. `site-scene`: 불투명 부지와 낮은 대비 주변, 지형을 따르는 경계, 운동장·주차장·녹지·광장·계단·진입구를 생성하고 기존 모델을 정렬한다.
3. `app`, `site-controls`, `hud`, `index`: 전체 조감도/정사영/자유 이동, 검색·목록·범례·북쪽·거리·레이어·카메라 복귀, 기존 내부도와 접근성을 통합한다.
4. `scripts`, 패키지 설정, 테스트: 버전 고정 로컬 Babylon 런타임, TS→JS 재현 빌드, 로컬 실행, 데이터·장면·UI 및 브라우저 검증.
5. 문서와 검토 이미지: 기능별 결과, 정확성, 출처, 미검증 항목, 실행 및 복구 기록.

## 주요 위험과 대응

- 현재 경계·건물 앵커·면적 불일치: 동일 원자료로 정합한다. 면적 숫자에 맞춘 임의 확대·축소는 금지한다.
- OSM/공개 안내 영역은 법적 소유 경계가 아니다. 실제 최신 필지·시설 도면을 확보하지 못한 항목은 미검증으로 유지한다.
- 기존 외관과 내부 평면은 개념 모델이며 새 지도 정합이 실측 높이·창 수·실 배치를 증명하지 않는다.
- 기존 모델의 부속 바닥은 지형 변경에 따라 뜨거나 묻힐 수 있다. 건물과 지면 시설을 따로 정합하고 실제 브라우저에서 확인한다.
- 시점·축척·사진 연도 차이는 출처 메타데이터와 미검증 기록으로 추적한다.
- 수목·라벨·외곽선이 작은 화면을 가릴 수 있다. 표시 수준을 조절하고 반응형/키보드 테스트를 수행한다.

## 검증

`npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`, `npm run check:generated`, `npm run test:browser`, `git diff --check`. 테스트는 실제 원자료 입력 검증, 폴리곤/좌표/연결성, NullEngine 장면, DOM 접근성, 실제 WebGL 화면의 로드·모드·상세·검색·모바일·내보내기를 구분한다. 자동 검증은 현장 측량·학교 확인을 대체하지 않는다.

## 롤백과 호환성

단계별 원자료와 생성 데이터를 구분해 보존한다. 기존 16개 외관 TS와 내부 데이터를 보존하며 신규 장면 및 통합 변경을 기능 단위로 되돌릴 수 있게 한다. 데이터베이스·인증·외부 계정은 없고 변경하지 않는다. 정적 사이트 배포 시 전체 빌드 디렉터리를 한 버전으로 교체하고 이전 디렉터리로 복귀한다. 웹에서 실시간 외부 지도를 호출하지 않는다.
